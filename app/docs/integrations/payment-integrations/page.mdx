# WhatsApp Payment Integration

WhatsApp Payments let you collect money inside WhatsApp—through live conversations, automated chatbot journeys, or follow-up notifications when a transaction succeeds or fails.

In Notifyy you connect a payment provider (such as **Razorpay** or **UPI VPA ID**), complete onboarding, then reuse that configuration wherever payments are supported.

---

## Open WhatsApp Payments

1. Log in to Notifyy.
2. Go to **Integrations** → **WhatsApp Payments**.

The **Configuration** tab lists your payment setups with provider, type, status, and **Actions**. Switch to **Events** when you need to configure automated payment notifications. Use search, status filters, and **Recently deleted** to manage records at scale.

## Create a payment configuration

Click **+ Create Configuration** to start. The wizard has three parts: choose a provider, enter configuration details, then connect and authorize the account.

<DocsVideo src="/docs/integrations/payment-integrations/recordings/create-payment.mp4" />

### Step 1: Select a payment provider

Pick the method you want customers to pay with:

- **Razorpay** — payment gateway checkout in WhatsApp
- **UPI VPA ID** — UPI-based collection

Some providers may show as **Coming Soon**. Select one and click **Next**.

### Step 2: Enter configuration details

| Field | Required |
|-------|----------|
| **Payment Configuration Name** | Yes — must be unique |
| **Merchant Category Code** | Optional |
| **Purpose Code** | Optional |

Click **Create** when the details are complete. The new row appears in the list—usually with status **Needs Connection** until onboarding finishes.

<DocsVideo src="/docs/integrations/payment-integrations/recordings/process.mp4" />

### Step 3: Connect and authorize your provider

Notifyy cannot charge customers until the provider account is linked.

1. On the configuration row, open **Actions** (or use the link icon) and choose **Generate onboarding link** / **Onboard**.
2. Click **Connect Now** — Notifyy opens the provider sign-in page in a new window.
3. **Log in** with your provider credentials. For **Razorpay**, use the same login as your Razorpay dashboard.
4. Review the access Notifyy is requesting, then click **Authorize** (or **Allow**).
5. When authorization succeeds, you return to Notifyy and status changes to **Active**.

<img src="/docs/integrations/payment-integrations/screenshots/generate-onboarding-link.png" alt="Generate onboarding link action on a payment configuration row" className="mx-auto rounded-lg border border-gray-200 shadow-sm my-6" />

If you selected **UPI VPA ID**, follow the same onboarding steps and sign in with your UPI provider when prompted.

<TipBox>
  Use a Razorpay merchant account that already supports WhatsApp Payments. Authorization can fail if the account is not enabled for the channel you need.
</TipBox>

<TipBox>
  Status still **Needs Connection**? Open **Actions** → **Manage connection status** and run **Connect Now** again.
</TipBox>

## Payment status

| Status | Meaning |
|--------|-----------|
| **Active** | Provider connected; ready for conversations, chatbots, and events |
| **Needs Connection** | Configuration saved but onboarding not finished |

## Use payments in conversations and chatbots

Once a configuration is **Active**, you can collect payments in two ways.

### Customer conversations

Send a payment request during a live WhatsApp chat using the active configuration.

### Chatbot journeys

In **WorkFlow Builder** → **Flow Management**, add a **Send a WhatsApp Payment** node:

1. Open or create a chatbot flow.
2. Add **Send a WhatsApp Payment** from Payments and integrations.
3. Select an **Active** configuration (Razorpay or UPI).
4. Wire the next step—for example, a **Conditions** node to branch on success vs. failure.

<TipBox>
  Only **Active** configurations appear in chatbot payment nodes. Finish Step 3 onboarding before building payment steps in your bot.
</TipBox>

See [Chatbot Configuration and Flow Management](/docs/chatbot) for full WorkFlow Builder guidance.

## Configuration Actions

Each row exposes **Actions** for day-to-day management:

- **View** — open configuration details
- **Edit** — update settings where allowed
- **Delete** — remove unused configurations
- **Manage connection status** — reconnect or verify provider authorization
- **Generate onboarding link** — resume or repeat provider connection

Search by **configuration name** or **display name**, and filter by status when you manage multiple setups.

---

## Delete a configuration

Configurations tied to **Chatbot Flows** cannot be deleted until they are removed from those flows.

If dependencies exist, an **Entity Usage** popup lists every reference. Detach the configuration from chatbots and other modules first, then delete.

<WarningBox>
  Deleting or disconnecting a configuration that is still used in a live chatbot will break payment steps for customers mid-journey.
</WarningBox>

---

## Recently deleted

Deleted configurations move to **Recently deleted**. From there you can **Restore** a setup or **Delete permanently**.

## Payment event configuration

Payment events send automatic WhatsApp messages when transaction status changes—success, failure, pending, or refund updates.

### Open the Events tab

1. Go to **Integrations** → **WhatsApp Payments**.
2. Open the **Events** tab.

The listing shows event type, message status, configuration status, event status, and **Actions** for each event.

### Supported events

Configure independently:

- Payment Success
- Payment Failed
- Payment Pending
- Refund Success
- Refund Failed

### Configure an event

1. Open **Actions** on the event row.
2. Click **Configure**.
3. Set **Channel Type**, **Sender**, **Event Type**, **Message Template**, and **Order Status**.
4. Choose an **approved WhatsApp template**—for example, a Payment Success template when a charge completes.
5. Map payment fields (status, amount, order ID, payment reference ID) to template variables.
6. Check the **preview panel** on the right, then save.

| Event state | Behavior |
|-------------|----------|
| **Configured** | Setup complete |
| **Not Configured** | Not set up yet |
| **Active** | Notifications send when the event fires |
| **Inactive** | Paused — no messages sent |

Only **Active** event configurations trigger WhatsApp notifications.

## Payments object in CRM

All WhatsApp payment transactions live under **CRM → Payments**.

Use this view to monitor activity in one place—Payment Success, Payment Pending, Payment Failed, Refund Initiated, Refunded, Refund Failed, and other transaction statuses.

1. Click **CRM**.
2. Select **Payments**.
